# Lantern's website

`https://lantern.boreale.dev/`: the protocol's page and its specification, in the fifteen languages of Boréale's sites (English at the root, each other one in its folder: `/fr/`, `/fr-ca/`, `/de/` ... `/zh-hant/`), and the error types the specification's `type` addresses lead to (`/errors/<name>/`, in English). Every link inside it is relative, so it works at another address too.

```sh
python3 tools/build_site.py build         # the pages (SITE_OFFLINE=1: without boreale.dev's versions)
python3 tools/check_site.py build         # links, anchors, catalogs, CSP, referrers, UTM tags, error types, drafts, demo
python3 tools/make_demo.py check build/demo   # the demo at Lantern Static, its trapped variant refused (tools/requirements.txt)
python3 -m http.server -d build           # then http://localhost:8000/
SITE_AXE=axe.min.js python3 tools/site_layout.py build   # phones to desktop, with axe (Playwright)
```

- `template.html` is every page's frame, `home.html` the protocol's page. Each `{{key}}` is a text of `i18n/<language>.json` (`en.json` the reference; the menu of Boréale's sites, the privacy texts and the footer's notice are boreale.dev's catalogs' word for word).
- **The specification** (`spec/`) is `SPEC.md`, rendered at each build by `build_site.py` (`blocks()`, the Markdown SPEC.md is written in, with the standard library only): each heading an anchor as GitHub makes it (`#42-handshake`), each `§ 4.2` a link to its section, its contents beside it. It stays in English in every language; the page around it is translated and says so.
- **Its drafts** (`spec/0.1/` ... `spec/0.5/`): SPEC.md as each draft was published, read from git at each build (`git show <commit>:SPEC.md`, the commits in `DRAFTS` of `build_site.py`), so that a published draft never changes; the workflow checks out the whole history for it (`fetch-depth: 0`). Each one says it is superseded (or, for the current draft, that `spec/` is its text with the fixes made since), says `noindex` and stays out of the sitemap; its relative links lead to the repository at its commit. A row of chips on every specification page leads to them (`drafts_nav()`). **`spec/changes/`** says what each draft changed: its entries of SPEC.md's "Changes", then the sections it added, changed (with the words added and removed), renamed, removed and renumbered against the draft before, read from the two texts (`outline()`, `compared()`).
- **Its translations** (`site/translations/`), informative only: `SPEC.fr.md` is the French text of the current draft, shown at `/fr/spec/` and `/fr-ca/spec/` with a banner saying that only the English text is authoritative. Its header (an HTML comment) names the English commit it translates and SPEC.md's SHA-256 at that commit, its banner and its links' words; its numbered headings take the English anchors (`#42-handshake`), and an unnumbered one gives its own (`## Modifications {#changes}`). The requirement ids, code, field names, JSON and the BCP 14 keywords stay as in English. `check_site.py` warns (never fails) when SPEC.md has changed since that commit, and while it has not, checks that every requirement id is in the translation and an anchor of its page. Other languages are welcome: see CONTRIBUTING.md.
- **The demo library** (`demo/`): a static library (SPEC.md § 21) of fictional games, homebrew and cheat sets, which `tools/make_demo.py` writes at each build from `site/demo/demo.json`, and its trapped variant (`demo/trapped/`), static libraries broken on purpose for testing clients (`site/demo/README.md`). Its page, `site/demo.html`, is in every language; the trapped libraries' page is in English, `noindex`, out of the sitemap and of `robots.txt`'s reach. The workflow runs the conformance suite against both: the demo must reach Lantern Static, each trapped library must fail the checks it names. Its files carry no tracking (`check_site.py` checks it): only the pages count visits.
- **The error types** (`errors/`): the table of SPEC.md's section "Errors" (§ 12 in 0.3), read from it, one row and one page per `code`, at the address its `type` gives (`https://lantern.boreale.dev/errors/account-frozen`). `check_site.py` fails when one of SPEC.md's error addresses has no page.
- The look is Boréale's (`branding/README.md` in JigSawFr/boreale): the night, the aurora once at the top, Sora, Figtree and JetBrains Mono served with the site (`assets/fonts/`, SIL Open Font License; the language menu's flags CC BY 4.0). `assets/mark.svg` is Lantern's mark (the frame in the aurora's colours, a lantern in snow, its flame lit), also the favicon and `assets/marks/lantern.svg`; `social-preview.html` is the source of `assets/social-preview.png`, taken with Chromium at 1280 × 640.
- **Requirement ids**: each `[L-5.2-3]` of SPEC.md is an anchor of the specification's page (`inline()`), which the traceability page links to.
- **Conformance** (SPEC.md § 17), in English like the specification: `conformance/` (the levels, read from § 17's table), `requirements/` (each requirement, from `tools/requirements.py`, and the checks of `conformance/run.py` that cover it, or why the suite cannot see it), `implementations/` (the registry, `registry.json`, schema 1: an implementation joins it by a pull request with the suite's report) and `badge/` (the "Lantern compatible" badges, one per level, written by `badge_svg()` into `assets/badges/lantern-<draft>-<level>.svg`, after Boréale's brand: the frame in the aurora's colours around the night, the lantern in snow). The home page's "Conformance" section links to them, and so does the footer. `check_site.py` checks that every requirement has its anchors, the registry its fields, every level its badge.
- **The header**: the name opens the menu of Boréale's sites (`switcher()`, `SITES` in `build_site.py`: boreale.dev's list, then Atlas and Lantern), each with its latest release from `https://boreale.dev/versions.json` (`versions_of()` reads `{"schema": 1, "projects": {...}}` and the flat shape of before; another schema shows no versions). The languages' menu leads to the same page in another language, and the choice is kept (`assets/lang.js`, `lantern-lang`).
- **Links out** (`links_out()`): every page says `<meta name="referrer" content="no-referrer">`; a link to another site has `rel="noreferrer"`, one to boreale.dev, its subdomains or github.com/JigSawFr keeps the origin (`referrerpolicy="strict-origin"`). A link to another of our sites carries `utm_source=lantern` and `utm_medium=nav`, `footer` or `link` (`utm()`), one to this site or anyone else none.
- **The audience**, counted by Umami Cloud: `assets/umami.js` is its tracker, served with the site (a copy of <https://cloud.umami.is/script.js>, Boréale's sites share it), which sends each page seen to `gateway.umami.is`, without cookie, and only from `lantern.boreale.dev` (`data-domains`), not from a preview or a local copy. Its site in Umami is Boréale's (`UMAMI_WEBSITE`), shared with the other projects' sites. The home page's privacy section says what it counts, and links to boreale.dev's privacy and legal notice.
- The Content-Security-Policy allows nothing but the site itself: no inline script or style, no font or script from elsewhere; the one address a page may send to is Umami's (`connect-src`).
- No e-mail address anywhere: contact goes through the repository's issues (`check_site.py` checks it).

`.github/workflows/site.yml` builds and checks it for each pull request touching it, and publishes main's on GitHub Pages (*Settings › Pages › Source: GitHub Actions*; the custom domain is written in `build/CNAME` too).
